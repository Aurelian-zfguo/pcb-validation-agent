# 踩坑记录

> 本文件收录项目 A/B 联动开发中解决过的有代表性的 Bug 和配置错误，供新会话快速排查。

## 1. .env 文件名多了 .txt 后缀

- 现象：配了密钥但读不到，报告归因列为空。
- 根因：Windows 记事本保存时自动加了 .txt 后缀，config.py 只认精确的 .env。
- 解决方案：改名为 .env（无后缀），并确认首行键名是 DEEPSEEK_API_KEY。

## 2. 依赖装错解释器（venv vs 全局 Python）

- 现象：PyCharm 提示"不满足软件包要求 pandas/openpyxl/pyyaml"。
- 根因：pip 装到了全局 Python，而 PyCharm 项目用的是 .venv。
- 解决方案：把依赖装进 .venv（用 PyCharm Terminal，它自动激活 venv），或 `".venv\Scripts\python.exe" -m pip install -r requirements.txt`。

## 3. pandas sheet_name=None 返回字典

- 现象：读 Excel 报 AttributeError: 'dict' object has no attribute 'columns'。
- 根因：pd.read_excel(sheet_name=None) 返回"所有 sheet 的字典"，不是第一个 sheet。
- 解决方案：sheet 为空时不传 sheet_name（读第一个），指定时才传 sheet_name=sheet。

## 4. & 优先级高于 > 导致条件被吞

- 现象：R1 规则在"在线数=0"时仍被误判为违规入仓。
- 根因：`df["入库数"]>0 & (...)` 被解析成 `入库数 > (0 & ...)`，在线数/已产出数条件失效。
- 解决方案：每个比较都加括号，如 `(df["入库数"]>0) & (df["在线数"]>0)`。

## 5. 隐藏 _行号 列干扰判重

- 现象：完全重复的两行检测不出来。
- 根因：_行号 列在质检判重前就加进去了，两行因行号不同而不被判定为"重复"。
- 解决方案：判重前 drop 掉 _行号 列。

## 6. B 服务连接被拒 + 超时太短（RAG 联动）

- 现象：跑 main.py 后报告归因无"【知识补充】"。
- 根因：① 127.0.0.1:8000 无服务监听（B 的 api.py 没启动）；② 超时 2 秒太短，B 首请求加载 BGE 模型会超时。
- 解决方案：确认 B 服务已启动（curl /health 返回 ok）+ 把检索超时调到 15 秒。

## 7. 知识只进 Prompt 不进输出

- 现象：报告"归因说明"列只有硬编码的预大率对比，没有"【知识补充】"制度条文。
- 根因：知识只拼进 Prompt，LLM 生成归因时不会原样输出"【知识补充】"前缀。
- 解决方案：在 attribute_anomalies 里把知识直接追加到归因说明输出，保证报告可见。

## 8. 波动条件方向写反

- 现象："剔除最高 > 平均 10% 即波动大"这条判断永远不触发。
- 根因：剔除最高恒 ≤ 平均（去掉最高值只会让均值下降），"剔除最高 > 平均"数学上不可能。
- 解决方案：改为"平均 > 剔除最高 × 1.5"（平均被异常高批次拉高 = 有波动）。

## 9. 补料日期带时分秒导致漏判

- 现象：同一天不同时刻的两次补投被漏判为"重复补投"。
- 根因：补料日期含时分秒，按完整时间戳判重无法识别"同一天"。
- 解决方案：判重前把补料日期归一化到"天"粒度（忽略时分秒）。

## 10. Windows 中文输出乱码

- 现象：测试/运行输出中文变乱码。
- 根因：Windows 控制台默认编码不是 UTF-8。
- 解决方案：运行命令加 PYTHONIOENCODING=utf-8，或代码里 sys.stdout.reconfigure(encoding="utf-8")。
